# Professional leave approvals and employee calendar

New requests follow Employee → Project Head / Site Head (or Project Manager) → HO Coordinator. The existing `status` remains `pending` through both stages and becomes `approved` only after HO approval. `approval_stage` tracks `pending_pm`, `pending_ho`, `accepted` or `rejected`. Either reviewer can reject at their stage; rejection requires a note. The applicant cannot review their own request and the two reviewers must be different employees.

Pending requests whose leave date is before the current IST date automatically become Rejected. This includes PM-pending and HO-pending requests. A primary-instance cron catches them every minute; leave/report schema entry points also catch up before reading, including after downtime. Current-day and future requests remain pending; approved/rejected decisions are preserved. Each expiry records a system audit with before/after snapshots, `auto_rejected_at`, an explanatory note and one applicant notification, and releases reserved quota. The additive `20261016_professional_leave_expiry.sql` migration installs the idempotent expiry function. Review also independently rejects stale requests.

Workspace → Team Leave Requests uses current designation assignments and explicit site access on every request. Head of Departments can view their assigned sites but cannot decide requests. The employee's Request Leave screen shows both reviewers, timestamps, notes and an expandable change history. Admin/supervisor direct decision endpoints return 403, preventing bypass of the required stages; allocation editing remains available under its existing permissions.

Leave requires an allocation for the selected leave type. All applicable monthly, quarterly, half-yearly and yearly limits apply to the requested date's period. Approved and pending requests consume available balance; rejection releases the reservation. Employee-row transaction locks serialize submissions, reviews and admin allocation edits. Quota is rechecked at each approval. Existing approved leave is preserved. Pending requests cannot be overwritten; rejected requests can be resubmitted and restart at PM. Existing punches or assigned Week Off prevent a new request or subsequent approval.

`professional_leave_request_logs` stores actor identity, time, note and complete before/after JSON snapshots in the same transaction as the request update. Allocation changes continue to use the existing allocation audit log. Week Off assignments use the existing effective-dated version history. Request/decision notifications target the applicant and the assigned reviewers at the pending stage.

Attendance displays Approved Leave after final approval and Unapproved Leave (Pending/Rejected) otherwise. Pending/rejected leave does not become paid approved leave. Employee calendar cells explicitly label assigned Week Off days, including upcoming days; today's no-punch refresh preserves Week Off/leave/holiday instead of overwriting it with Absent. Home retains the existing Week Off today indicator. Attendance reports resolve PM/HO reviewer names as well as legacy admin names.

The additive migration `20261015_professional_leave_workflow.sql` is applied transactionally by `ensureProfessionalLeaveSchema` on first use. No live database was changed during development. Existing approved/rejected requests are mapped to final stages; existing pending requests start with PM.

API: existing professional leave request/list/balance endpoints use the new workflow. Balance optionally takes `date=YYYY-MM-DD`. Team reviewers use `GET /api/professional/leave/team-requests?status=pending&month=YYYY-MM` (month optional; latest 500) and `POST /api/professional/leave/team-requests/:id/review` with `{decision:"allow"|"reject",note:"..."}`.

Local verification: `node tests/professionalLeaveWorkflow.integration.js` uses isolated PGlite and no live connections. Run the punch-cutoff and team-attendance integration suites plus weekly-off verification with `--local-pg` for regression coverage.
